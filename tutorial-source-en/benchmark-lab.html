Start with these three concurrency controls

ControlSetting hereWhat it controls
Collector --concurrency1How many tasks the Collector submits to Environment and waits for at once. Setting 4 does not make one model call four times faster.
Environment max_concurrent_episodes1 (lab.yaml)How many episodes actually run at once. If only the Collector limit rises to 4, the extra requests still queue.
Hermes concurrency / model / provider capacityHermes inherits 32; external capacity depends on deploymentDownstream components have their own limits. Check capacity before adjusting Collector and Environment together. FastAPI worker count is a different control.

To try concurrency 2, change max_concurrent_episodes in lab.yaml to 2. Restart this run's services in Terminal A, then use a new result directory with --concurrency 2. In contrast, --num-repeats 2 samples each task twice. Sample count and simultaneous task count are separate settings.

Resume after an interruption, and understand partial results

A normal eval run overwrites output at the same path by default. Use a new directory for a new experiment. To resume the same run, preserve its tasks, routing, materialized inputs, and rollouts. Add --resume to the otherwise identical collection command. Do not regenerate a new taskset with the conversion script and treat it as the original experiment.

Native task input lives in task_input. The current Collector does not apply top-level Responses overrides such as --temperature or --max-output-tokens to it. Set these values when generating input or in the relevant Agent configuration, then check with env resolve.

To inspect only completed tasks, add ++allow_partial_rollouts=True to eval profile. Tasks with no output are then excluded. Report the completed and expected counts together. A mean over a partial sample is not the full benchmark score.

Why do we still need eval run after startup succeeds?

env start prepares the services to answer requests. eval run starts the Collector that sends those requests. eval profile reads saved records and computes statistics without calling the model again. The three commands manage service lifetimes, task execution, and result analysis.
