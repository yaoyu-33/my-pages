How do these names connect?

weather_demo:                  # Runtime instance name
  resources_servers:           # Component type
    example_single_tool_call:  # Implementation directory
      entrypoint: app.py       # Entrypoint file
      host: 127.0.0.1
      port: 18080
      domain: agent

This is the instance section from the exercise configuration, not a complete benchmark recipe. The config type declared on the class receives these instance settings. Other services find it through ServerRef.name = weather_demo. The URL path /get_weather comes from route registration.

When should you write FastAPI directly?

For a small standalone service, you can create app = FastAPI(), register routes with decorators, and start it with Uvicorn. Gym adds shared configuration, clients, sessions, error handling, and observability.

When reading Gym code, start with the handler as ordinary Python, then follow the shared infrastructure. When building a Gym component, inheriting a base class saves repeated protocol and lifecycle code.

Instance fields in one process are not shared across workers. If you add workers, check where state and concurrency limits apply.

Try it: download the launcher and send two requests

Use a Gym checkout at this tutorial’s revision, with dependencies installed, and its Python environment. The launcher listens only on 127.0.0.1. It needs no API key, Head service, or model. Port 1 in the head_server configuration is only a placeholder required by the client configuration. The weather and scoring routes never access it.

Terminal A: replace the download path with the actual file location. Keep this terminal open after Uvicorn running appears.

cd /path/to/pinned/Gym
.venv/bin/python /path/to/download/weather-lab.py \
  --gym-root "$PWD" --port 18080
# To finish: return to this terminal and press Ctrl+C

Terminal B: send valid JSON first, then deliberately omit city.

curl -i http://127.0.0.1:18080/get_weather \
  -H 'Content-Type: application/json' \
  -d '{"city":"San Francisco"}'

curl -i http://127.0.0.1:18080/get_weather \
  -H 'Content-Type: application/json' \
  -d '{}'

# You can also open http://127.0.0.1:18080/docs to inspect the app’s endpoints

Expect 200 for the first request and 422 for the second. If the port is busy, choose another --port and update the request URL too. This script teaches how one service starts. Open the answer

app is the FastAPI app; "/get_weather" is the request path; self.get_weather is a method bound to the current service object. Registration happens at startup. The handler body runs only when a matching request passes input validation.

For the next service you read, find these five things: configuration type → request / response types → handler → route registration (possibly in a base class) → startup entry point.
