什么时候该直接写 FastAPI？

普通的小服务可以直接写 app = FastAPI()，用装饰器注册路由，再用 Uvicorn 启动。Gym 在这之上统一提供了配置、客户端、会话、故障处理和观测。

读 Gym 代码时，可以先把业务函数当普通 Python 读，再去补公共基础设施这一层。自己写 Gym 组件时，继承基类能省掉大量重复的协议和生命周期代码。

注意：一个进程里的实例字段，并不会在多个 worker 之间共享。增加 worker 时，要重新确认状态和并发限制分别作用在哪个范围。

现在你来读一行：app.post("/get_weather")(self.get_weather) 里，三个名字分别是什么？
展开一起核对

app 是 FastAPI 应用；"/get_weather" 是请求路径；self.get_weather 是当前服务对象绑定好的函数。注册发生在启动时；只有当匹配的请求通过输入校验后，函数体才会执行。

下次读别的服务时，先找这五样：配置类型 → 请求/响应类型 → 业务处理函数 → 路由注册（也可能在父类）→ 启动入口。
