什么时候该直接写 FastAPI？

普通小服务可以直接写 app = FastAPI()、装饰路由，再用 Uvicorn 启动。Gym 在这之上复用配置、客户端、会话、故障处理和观测。

读 Gym 时可以先把业务函数当普通 Python 读，再补这层公共基础设施。接入一个 Gym 组件时，复用基类能减少重复的协议与生命周期代码。

不要把单个进程中的实例字段当成所有 worker 共享的状态；增加 worker 时，要重新确认状态和并发限制的范围。

现在你来读一行：app.post("/get_weather")(self.get_weather) 里，三个名字分别是什么？
展开一起核对

app 是 FastAPI 应用；"/get_weather" 是请求路径；self.get_weather 是当前服务对象绑定好的函数。注册发生在启动期间，函数体在匹配的请求通过输入校验后执行。

如果下一步换一个服务读，先找这五样：配置类型 → 请求/响应类型 → 业务处理函数 → 路由注册（也可能在父类）→ 启动入口。
